# MASHMAUET — эксплуатация локального backend

## Обычный запуск

Откройте `START-MASHMAUET.cmd`. Приложение доступно только на этом компьютере:

`http://127.0.0.1:3000`

Имя пользователя и пароль MASHMAUET не требуются. Чат использует текущую сессию
Codex/ChatGPT. Если она истекла, выполняется официальный одноразовый вход.

## Где находятся данные

Рабочие данные лежат в `local-data/`:

- `projects/` — активные проекты, их материалы, извлечённый текст и версии;
- `archive/` — архивированные проекты;
- `backups/` — автоматические, ручные и страховочные копии;
- `global-rules.json` — подтверждённые общие правила;
- `logs/application.log` — технические события без текста чата и файлов.

Папка `local-data/` не входит в Git. Не удаляйте её при очистке проекта.

## Чтение и исправление материалов

В `projects/:projectId/derived/:materialId/` отдельно сохраняются машинно
извлечённый текст, анализ Codex, ручная правка и подготовленные страницы/кадры.
Ручная правка имеет приоритет в проектном чате, но не заменяет и не удаляет
исходное извлечение. Повторное чтение сохраняет правку и помечает её для
повторной проверки.

Для видео исходный файл остаётся в папке материалов, а HTML-страница локально
создаёт до 12 ключевых JPEG-кадров. Они используются для визуального анализа в
хронологическом порядке. Система не утверждает, что распознала речь из звуковой
дорожки, если отдельной расшифровки нет.

## Быстрая диагностика

1. Откройте `http://127.0.0.1:3000/local/health`.
2. Нормальный ответ содержит `status: "ok"`, `writable: true` и пустой
   `corruptEntries`.
3. Выполните в PowerShell из папки проекта:

```powershell
npm run check
npm run test:e2e
```

Первая команда проверяет типы и запускает модульные/API-тесты. Вторая поднимает
приложение во временном локальном хранилище и проверяет в Chromium основной
рабочий путь, мобильный интерфейс и извлечение кадров из видео. Временные данные
удаляются только из `.tmp/playwright/run-*` после проверки.

GitHub Actions выполняет обе команды при каждом `push` и `pull_request`. При
ошибке браузерного теста сохраняются снимок, trace и HTML-отчёт на семь дней.

## Резервные копии

При первом запуске каждого дня создаётся автоматическая копия. Ручную копию
можно создать через `POST /local/backups` с телом:

```json
{ "label": "Перед важным изменением" }
```

Список копий: `GET /local/backups`.

## Восстановление

Восстановление заменяет набор активных проектов содержимым выбранной копии.
Перед заменой backend автоматически создаёт страховочную копию текущего состояния.

Запрос:

`POST /local/backups/:backupId/restore`

Обязательное тело:

```json
{ "confirm": true }
```

Копия сначала разворачивается во временную папку и проверяется. Рабочие проекты
заменяются только после успешной проверки. При ошибке прежние данные остаются на
месте.

## Архивирование проекта

Вместо безвозвратного удаления используется архив. Перед архивированием также
создаётся страховочная копия. Единственный активный проект архивировать нельзя.

- архивировать: `POST /local/projects/:id/archive` с `{ "confirm": true }`;
- список: `GET /local/archived-projects`;
- вернуть: `POST /local/archived-projects/:id/restore`.

## Ограничения безопасности

- сервер слушает только `127.0.0.1`;
- запросы с внешним `Origin`, неправильным `Host` или `cross-site` отклоняются;
- максимальный размер одного файла — 100 МБ;
- максимальный текст сообщения чата — 30 000 символов;
- изменение документа и правил текущего проекта из чата применяется только после
  подтверждения; общие правила системы через проектный чат недоступны;
- взаимосвязанные изменения документа проверяются и применяются атомарно, а
  устаревшее предложение отклоняется после любой последующей правки документа;
- временный разрыв потока Codex не останавливает локальный сервер; окончательная
  ошибка сохраняется рядом с вопросом и может быть повторена без нового ввода;
- восстановление и архивирование требуют отдельного подтверждения;
- внутренние пути файлов и идентификаторы Codex не выдаются интерфейсу.

## Проектный процесс DEKEL

DEKEL хранится в `HOMER/DEKEL` как постоянный глобальный прайс-лист системы: его
не нужно и нельзя требовать загружать в каждый проект. Это единственный источник
кодов и цен по умолчанию. Любой другой прайс-лист полностью исключён из
ценообразования независимо от расположения — в материалах проекта, глобальной
папке или другом каталоге. Система не предлагает и не спрашивает о его
использовании. Исключение возникает только после прямой команды владельца, в
которой назван конкретный файл и потребовано использовать именно его; такое
исключение не меняет DEKEL как постоянный системный источник по умолчанию.
Конкретный XLSX зафиксирован в `HOMER/DEKEL/default-dekel.json`; наличие других
прайс-листов в любых папках не меняет этот выбор.

DEKEL подключён к локальным проектам отдельной проверочной сессией. Анализ берёт
работы и количества из текущего `כתב כמויות`, выбирает рекомендуемые строки из
реального XLSX и сохраняет до трёх кандидатов. Пользователь может ввести любой
код, существующий в фиксированном DEKEL, исправить количество или исключить
строку. Несовместимая единица блокирует применение; ввод точного подтверждённого
кода явно исправляет единицу по DEKEL. Устаревшая сессия блокируется, если
`כתב כמויות` изменился после анализа. Исключённая строка удаляется только при
подтверждённом применении.

Перед применением система сверяет нетто, НДС 18%, итог с НДС, агрегированный
`פירוט האומדן`, надбавки 7.4%, 5.4% и 2.7% от базы с НДС и общий итог до агоры.
Применение требует подтверждения, создаёт версию документа, хранит цены без НДС
и добавляет доказательную сноску с именем файла, кодом, главой и номером строки.

## Справочные источники 3210 и «Синяя книга»

PDF из `HOMER/3210` и `HOMER/BLUE BOOK` являются постоянными глобальными
справочниками и не загружаются в проекты. Перед запросом к проектному чату
backend сначала проверяет релевантность вопроса. При необходимости он выбирает
договорный 3210 либо технические главы по теме и кодам DEKEL, извлекает только
нужные PDF и передаёт до шести фрагментов с именем файла и страницей.

Производный текстовый кэш хранится в `local-data/knowledge-cache`. Он не является
источником истины и автоматически перестраивается, если размер или дата PDF
изменились. Повреждение кэша также приводит к повторному чтению исходного PDF.

Интеграция не имеет элементов интерфейса и не меняет итоговый документ. Источники
имеют статус `reference_only`; их применимость определяется материалами
конкретного проекта. Наличие листа исправлений передаётся в контекст как
предупреждение, а выбор между редакциями не делается автоматически.
